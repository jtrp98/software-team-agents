# Test-planner rationale

The role is a conditional specialist, not a mandatory pipeline stage. Canonical PlanTask acceptance, validation, evidence, and compatibility fields cover ordinary work while `test-pyramid.yaml` supplies the deterministic minimum. The closed triggers `cross-task`, `multi-system`, `migration`, `security`, and `release` select one shared test-plan only when affected tasks need coordinated strategy. The prompt retains cross-boundary test-level selection and contract/unknown-behaviour judgments that cannot be inferred from a document schema.
